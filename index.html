Start working with the code in an IDE

SMART WATER APP — Student instructions
Clone · Install once · Run locally · Modify in VS Code

The Smart Water App is a ready-to-run Vite project. Install Node.js once, then use two terminal commands to start the local app. You can develop the interface and add modules without changing the shared baseline data.

1 · CLONEGet SmartWaterApp from GitHub2 · INSTALLRun npm install once3 · STARTRun the local Vite app4 · EDITModify it in VS Code5 · BUILDMake a static production build

1. Install the tools

  • Install Node.js 22.12 or newer. Node includes npm.
  • Install Git and Visual Studio Code.
  • In VS Code, you may add GitHub Copilot or another AI coding assistant. AI assistance is optional.

2. Clone the project

In VS Code, press Ctrl+Shift+P, choose Git: Clone, and paste the repository address. Or run these commands in Git Bash:

git clone https://github.com/smart-water-EDU/SmartWaterApp.git
cd SmartWaterApp

Open the resulting SmartWaterApp folder in VS Code. Clone only once; later reopen the same folder.

3. Install and start the app

Open Terminal → New Terminal in VS Code. From the project folder, run:

npm install
npm run dev

Vite opens the app in your browser at http://127.0.0.1:5173/. Keep the terminal running while you work. Save code changes and Vite refreshes the browser. To stop the app, press Ctrl+C in the terminal.

To check a production build, run npm run build. The ready-to-deploy files appear in dist/. This build command does not change the baseline dataset.

4. Find the source files

  • src/app.js connects the tabs, clock, meters, selectors and panels.
  • src/engine.js, src/sensors.js and src/pump-model.js hold separate calculation modules.
  • src/components/ contains the chart and interactive network code. The building SVG is embedded in index.html.
  • src/styles/ contains the responsive visual design.
  • data/ contains editable JSON/CSV inputs. public/data/datasets.js is generated from the JSON files.
  • public/assets/ contains the local building image, logo and diagram artwork.

5. Make a safe first change

Open Copilot Chat or your preferred coding assistant and ask it to explain the relevant file before editing. Start with a small style change in src/styles/. For example:

“Make the selected tab slightly easier to distinguish. Change only the relevant CSS in src/styles/. Do not edit data, HTML, calculations, chart values or other styles. Tell me which rule you will edit first.”

Review edits in VS Code Source Control, then use git diff to inspect them. Keep your practice changes local; do not push to the shared main branch.

6. Update your local copy

Before pulling updates, save or back up your own edits. In the project terminal run:

git pull origin main

If Git reports a conflict, ask your teacher for help. Do not force-push or delete files to resolve it.

STUDENT GUIDE

Further development ideas

Build new features as small, testable modules. Keep educational assumptions visible and preserve the simulated baseline while evaluating alternative scenarios.

Suggested extensions

  1. Tenant change-of-use scenarios. Calculate proposed hourly demand from unit area, consumption profile, opening schedule, occupancy and customer fullness. Compare it with a separate copy of the existing baseline.
  2. Rainwater collection. Add rainfall inputs, roof catchment and runoff assumptions, first-flush diversion, filtration, tank storage, overflow and non-potable demand allocation.
  3. Sewage heat recovery. Model sewage flow and temperature, exchanger performance, heat demand, recovered energy, added pumping energy and maintenance constraints.
  4. Water balance and sensor quality. Add pressure or water-quality signals, meter uncertainty, missing data and sensor-offset scenarios, with explanations of how these affect alarms.
  5. Demand and pump control. Compare simple schedules or pressure rules with predictive methods in simulation. Keep all pump actions virtual; this application has no real equipment control.
  6. Data and usability. Add import validation, scenario export, clearer units, keyboard support and focused tests for calculations and totals.
Good extension pattern: document inputs, outputs, units and assumptions; isolate calculations; add a small test; connect the result through a narrow UI boundary; and leave unrelated features untouched.
